Day 75 - JavaScript Callbacks and Promises

🎥 Watch Tutorial #75

In this tutorial, we learn about callbacks and promises in JavaScript. These concepts are used to handle asynchronous operations such as loading scripts, fetching data from APIs, reading files, waiting for timers, and communicating with servers. Callbacks allow one function to run after another task is completed, while promises provide a cleaner and more structured way to handle successful and failed asynchronous operations.

What is Synchronous JavaScript?

Synchronous JavaScript executes code one statement at a time in a fixed sequence. Each statement waits for the previous statement to complete.

console.log("First"); console.log("Second"); console.log("Third");

The output will always follow the same order:

First Second Third

What is Asynchronous JavaScript?

Asynchronous JavaScript allows some tasks to run later without blocking the remaining code.

console.log("Start"); setTimeout(function() { console.log("Timer completed"); }, 2000); console.log("End");

The output will be:

Start End Timer completed

The timer does not stop the remaining JavaScript code from executing.

Why Do We Need Asynchronous JavaScript?

  • Fetching data from an API.
  • Loading external JavaScript files.
  • Reading files.
  • Working with databases.
  • Waiting for timers.
  • Uploading images or documents.
  • Sending requests to a server.
  • Downloading data without freezing the webpage.

What is a Callback Function?

A callback is a function passed as an argument to another function. The callback function is executed later when a task is completed.

function greet(name, callback) { console.log("Hello " + name); callback(); } function completeMessage() { console.log("Greeting completed"); } greet("Sangam", completeMessage);

In this example, completeMessage is passed to greet as a callback function.

Basic Callback Example

function calculate(a, b, callback) { let result = a + b; callback(result); } function displayResult(value) { console.log("Result:", value); } calculate(10, 20, displayResult);

The calculate function performs the calculation and passes the result to the callback function.

Passing an Anonymous Function as Callback

A callback function does not always need a separate function name. We can pass an anonymous function directly.

function processUser(name, callback) { console.log("Processing user:", name); callback(); } processUser("Sangam", function() { console.log("User processed successfully"); });

Arrow Function as Callback

function performTask(callback) { console.log("Task started"); callback(); } performTask(() => { console.log("Task completed"); });

Arrow functions are commonly used as callback functions because they provide shorter syntax.

Callback with setTimeout()

The function passed inside setTimeout() is also a callback function.

setTimeout(function() { console.log("This callback runs after 2 seconds"); }, 2000);

The browser executes the callback after the timer delay is completed.

Callback in Event Listener

let button = document.querySelector("#btn"); button.addEventListener("click", function() { console.log("Button clicked"); });

The function passed to addEventListener() is a callback. It runs only when the click event occurs.

Loading a Script Using Callback

JavaScript can dynamically create and load an external script file.

function loadScript(src, callback) { let script = document.createElement("script"); script.src = src; script.onload = function() { console.log("Script loaded successfully"); callback(); }; document.head.append(script); } loadScript("script.js", function() { console.log("Callback executed"); });

The callback runs only after the external script has loaded successfully.

Handling Script Loading Errors

A script may fail to load because of an incorrect URL, network problem, or missing file.

function loadScript(src, callback) { let script = document.createElement("script"); script.src = src; script.onload = function() { callback(null, src); }; script.onerror = function() { callback(new Error("Script loading failed")); }; document.head.append(script); } loadScript("script.js", function(error, src) { if (error) { console.log(error); return; } console.log("Script loaded:", src); });

The callback receives an error when the script fails to load.

Error-First Callback Pattern

The error-first callback pattern sends the error as the first callback argument and successful data as the second argument.

function getData(callback) { let success = true; if (success) { callback(null, "Data received"); } else { callback(new Error("Unable to receive data"), null); } } getData(function(error, data) { if (error) { console.log(error.message); return; } console.log(data); });
Argument Purpose
First argument Contains error information
Second argument Contains successful result or data

What is Callback Hell?

Callback hell occurs when multiple callbacks are deeply nested inside one another. The code becomes difficult to read, understand, debug, and maintain.

loadScript("script1.js", function() { loadScript("script2.js", function() { loadScript("script3.js", function() { loadScript("script4.js", function() { console.log("All scripts loaded"); }); }); }); });

The deeply nested structure is also known as the pyramid of doom.

Problems with Callback Hell

  • Code becomes deeply nested.
  • Error handling becomes difficult.
  • Code readability decreases.
  • Debugging becomes complicated.
  • Functions become strongly dependent on one another.
  • Code maintenance becomes difficult.
  • Reusable logic becomes harder to create.

What is a Promise?

A promise is an object that represents the eventual completion or failure of an asynchronous operation.

let promise = new Promise(function(resolve, reject) { let success = true; if (success) { resolve("Task completed successfully"); } else { reject("Task failed"); } });

The resolve function is used when the operation is successful, while reject is used when the operation fails.

Promise States

State Meaning
Pending The asynchronous operation is still running
Fulfilled The operation completed successfully
Rejected The operation failed
Pending ↓ Fulfilled or Rejected

Once a promise becomes fulfilled or rejected, its state cannot be changed again.

Creating a Promise

let promise = new Promise(function(resolve, reject) { console.log("Promise is pending"); setTimeout(function() { resolve("Promise fulfilled"); }, 2000); });

The promise starts in the pending state and becomes fulfilled after two seconds.

Consuming a Promise with then()

The then() method runs when a promise is fulfilled.

let promise = new Promise(function(resolve, reject) { setTimeout(function() { resolve("Data received successfully"); }, 2000); }); promise.then(function(result) { console.log(result); });

The result passed to resolve() becomes available inside the then() method.

Handling Promise Errors with catch()

The catch() method runs when a promise is rejected.

let promise = new Promise(function(resolve, reject) { setTimeout(function() { reject(new Error("Unable to fetch data")); }, 2000); }); promise.catch(function(error) { console.log(error.message); });

Using then() and catch() Together

let promise = new Promise(function(resolve, reject) { let success = true; if (success) { resolve("Operation completed"); } else { reject(new Error("Operation failed")); } }); promise .then(function(result) { console.log(result); }) .catch(function(error) { console.log(error.message); });

Handling Success and Failure Inside then()

The then() method can also receive two functions. The first handles success and the second handles failure.

promise.then( function(result) { console.log("Success:", result); }, function(error) { console.log("Error:", error); } );

However, using a separate catch() method is usually easier to read.

Promise with setTimeout()

function waitForTwoSeconds() { return new Promise(function(resolve, reject) { setTimeout(function() { resolve("Two seconds completed"); }, 2000); }); } waitForTwoSeconds() .then(function(message) { console.log(message); });

Returning Data from a Promise

function getUserData() { return new Promise(function(resolve, reject) { let user = { name: "Sangam", role: "Software Developer" }; resolve(user); }); } getUserData() .then(function(user) { console.log(user.name); console.log(user.role); });

Promise Chaining

Promise chaining allows multiple asynchronous tasks to run one after another using multiple then() methods.

let promise = new Promise(function(resolve, reject) { resolve(10); }); promise .then(function(value) { console.log(value); return value * 2; }) .then(function(value) { console.log(value); return value * 3; }) .then(function(value) { console.log(value); });

Each then() method receives the value returned by the previous then() method.

Returning a New Promise from then()

function stepOne() { return new Promise(function(resolve) { setTimeout(function() { console.log("Step 1 completed"); resolve(); }, 1000); }); } function stepTwo() { return new Promise(function(resolve) { setTimeout(function() { console.log("Step 2 completed"); resolve(); }, 1000); }); } stepOne() .then(function() { return stepTwo(); }) .then(function() { console.log("All steps completed"); });

Promise Chaining for Script Loading

function loadScript(src) { return new Promise(function(resolve, reject) { let script = document.createElement("script"); script.src = src; script.onload = function() { resolve(src); }; script.onerror = function() { reject(new Error("Script loading failed")); }; document.head.append(script); }); } loadScript("script1.js") .then(function(src) { console.log(src + " loaded"); return loadScript("script2.js"); }) .then(function(src) { console.log(src + " loaded"); return loadScript("script3.js"); }) .then(function(src) { console.log(src + " loaded"); }) .catch(function(error) { console.log(error.message); });

Promise chaining avoids deeply nested callbacks and makes asynchronous code easier to follow.

Callback vs Promise

Callback Promise
Function passed as an argument Object representing a future result
Can create nested code Supports clean chaining
Error handling can become difficult Errors can be handled using catch()
Useful for simple operations Better for multiple asynchronous operations
May create callback hell Reduces callback nesting
Older asynchronous pattern Modern structured asynchronous pattern

Promise Executor Function

The function passed to the Promise constructor is called the executor function.

let promise = new Promise(function(resolve, reject) { console.log("Executor function started"); resolve("Completed"); });

The executor function runs immediately when the promise is created.

Resolve and Reject

let promise = new Promise(function(resolve, reject) { let age = 20; if (age >= 18) { resolve("Eligible"); } else { reject(new Error("Not eligible")); } }); promise .then(function(message) { console.log(message); }) .catch(function(error) { console.log(error.message); });

A Promise Settles Only Once

A promise can be resolved or rejected only once. Any later calls to resolve or reject are ignored.

let promise = new Promise(function(resolve, reject) { resolve("First result"); resolve("Second result"); reject("Error"); }); promise.then(function(result) { console.log(result); });

Only First result will be used.

finally() Method

The finally() method runs after the promise is settled, whether it is fulfilled or rejected.

let promise = new Promise(function(resolve, reject) { resolve("Data loaded"); }); promise .then(function(result) { console.log(result); }) .catch(function(error) { console.log(error); }) .finally(function() { console.log("Operation finished"); });

finally() is commonly used to hide loading indicators or perform cleanup operations.

Complete Promise Example

function checkNumber(number) { return new Promise(function(resolve, reject) { setTimeout(function() { if (number > 0) { resolve("Number is positive"); } else { reject(new Error("Number is not positive")); } }, 1000); }); } checkNumber(10) .then(function(result) { console.log(result); }) .catch(function(error) { console.log(error.message); }) .finally(function() { console.log("Number checking completed"); });

Best Practices

  • Use callbacks for simple asynchronous tasks.
  • Use promises for multiple dependent operations.
  • Always handle rejected promises.
  • Use Error objects while rejecting promises.
  • Return values from then() for promise chaining.
  • Return promises when the next task is asynchronous.
  • Avoid deeply nested callback functions.
  • Keep asynchronous functions small and reusable.
  • Use meaningful names for callback functions.
  • Use finally() for cleanup operations.

Common Mistakes

  • Calling a callback immediately instead of passing it.
  • Forgetting to execute the callback.
  • Creating deeply nested callback functions.
  • Not handling errors in callback functions.
  • Forgetting to return a promise from a function.
  • Forgetting to return a value from then().
  • Not adding catch() to handle rejected promises.
  • Using resolve and reject multiple times.
  • Assuming promises execute only when then() is called.
  • Writing all asynchronous logic inside one large function.

Important Points

  • A callback is a function passed to another function.
  • Callbacks execute after a task or event is completed.
  • Timers and event listeners use callback functions.
  • Deeply nested callbacks create callback hell.
  • A promise represents a future asynchronous result.
  • A promise can be pending, fulfilled, or rejected.
  • resolve() fulfils a promise.
  • reject() rejects a promise.
  • then() handles fulfilled promises.
  • catch() handles rejected promises.
  • finally() runs after promise settlement.
  • Promise chaining handles dependent operations.
  • A promise can settle only once.
  • The promise executor runs immediately.
  • Promises make asynchronous code easier to manage.

Interview Questions

  1. What is a callback function?
    A callback is a function passed as an argument to another function and executed later.
  2. Why are callbacks used?
    Callbacks are used to execute code after another task, event, or asynchronous operation is completed.
  3. What is callback hell?
    Callback hell is a situation where multiple callbacks are deeply nested, making code difficult to read and maintain.
  4. What is a promise?
    A promise is an object representing the future completion or failure of an asynchronous operation.
  5. What are the three promise states?
    Pending, fulfilled, and rejected.
  6. What does resolve() do?
    resolve() changes a pending promise to the fulfilled state.
  7. What does reject() do?
    reject() changes a pending promise to the rejected state.
  8. What does then() do?
    then() handles the successful result of a promise.
  9. What does catch() do?
    catch() handles promise rejection and errors.
  10. What does finally() do?
    finally() runs after a promise is either fulfilled or rejected.
  11. What is promise chaining?
    Promise chaining means connecting multiple then() methods so asynchronous tasks execute in sequence.
  12. Can a promise be resolved more than once?
    No. A promise settles only once.
  13. When does the promise executor function run?
    It runs immediately when the promise is created.
  14. What is the difference between callbacks and promises?
    Callbacks pass functions into other functions, while promises provide an object-based and chainable way to handle asynchronous results.
  15. Why are promises preferred over deeply nested callbacks?
    Promises improve readability, support chaining, and provide centralized error handling.

Final Takeaways

Callbacks and promises are essential concepts for handling asynchronous JavaScript operations. A callback allows a function to run after another operation is completed, but deeply nested callbacks can create callback hell. Promises provide a cleaner solution by representing future results through pending, fulfilled, and rejected states. Using then(), catch(), finally(), and promise chaining, developers can create readable and maintainable asynchronous workflows. These concepts are heavily used while working with APIs, databases, file uploads, authentication, server communication, and modern web applications.
