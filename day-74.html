Day 74 - Events, Event Bubbling, setInterval & setTimeout

🎥 Watch Tutorial #74

This tutorial explains how JavaScript responds to user actions through events. It covers event handlers, the addEventListener() method, common mouse and keyboard events, the event object, event bubbling, stopPropagation(), setTimeout(), setInterval(), clearTimeout(), and clearInterval(). These concepts are essential for creating interactive buttons, forms, menus, games, notifications, sliders, counters, dashboards, and other dynamic web application features.

What are JavaScript Events?

A JavaScript event is an action or occurrence detected by the browser. JavaScript can listen for that event and run a function in response.

User Action ↓ Browser Detects Event ↓ Event Listener Runs ↓ Callback Function Executes ↓ Webpage Updates

Why are Events Important?

  • Handle button clicks.
  • Validate forms.
  • Detect keyboard input.
  • Open menus and modals.
  • Create sliders and games.
  • Update content dynamically.
  • Respond to mouse movement.
  • Build interactive web applications.

Using addEventListener()

The addEventListener() method attaches an event listener to an HTML element.

let button = document.querySelector("#btn"); button.addEventListener("click", function() { alert("Button was clicked"); });

When the user clicks the button, the callback function executes.

Named Event Handler

Instead of writing the complete function inside addEventListener(), we can create a separate named function.

let button = document.querySelector("#btn"); function handleClick() { console.log("Button clicked"); } button.addEventListener("click", handleClick);

Important

  • Pass the function name without parentheses.
  • handleClick passes the function reference.
  • handleClick() runs the function immediately.

Common JavaScript Events

Event Purpose
click Runs when an element is clicked
dblclick Runs when an element is double-clicked
mouseenter Runs when the mouse enters an element
mouseleave Runs when the mouse leaves an element
keydown Runs when a keyboard key is pressed
keyup Runs when a keyboard key is released
input Runs when input value changes
change Runs when a form value is changed
submit Runs when a form is submitted

Mouse Events Example

let box = document.querySelector(".box"); box.addEventListener("dblclick", function() { box.innerText = "Double-click detected"; }); box.addEventListener("mouseenter", function() { console.log("Mouse entered"); }); box.addEventListener("mouseleave", function() { console.log("Mouse left"); });

Keyboard Events Example

let input = document.querySelector("#name"); input.addEventListener("keydown", function(event) { console.log("Pressed key:", event.key); });

The event.key property tells us which keyboard key was pressed.

The Event Object

When an event occurs, the browser automatically passes an event object to the callback function.

let button = document.querySelector("#saveBtn"); button.addEventListener("click", function(event) { console.log(event.type); console.log(event.target); console.log(event.currentTarget); });
Property Meaning
event.type Name of the event
event.target Element where the event started
event.currentTarget Element whose listener is running
event.key Keyboard key that was pressed

event.target vs event.currentTarget

The event.target property refers to the element where the event originally occurred, while event.currentTarget refers to the element whose event listener is currently executing.

<button id="btn"> <span>Save</span> </button> let button = document.querySelector("#btn"); button.addEventListener("click", function(event) { console.log(event.target); console.log(event.currentTarget); });

If the span is clicked, event.target can be the span, but event.currentTarget will be the button.

What is Event Bubbling?

Event bubbling is the process in which an event starts from the innermost target element and then moves upward through its parent elements.

Button Click ↓ Child Element Listener ↓ Parent Element Listener ↓ Grandparent Listener

Event Bubbling Example

<div class="container"> <div class="child"> <button class="button">Click Me</button> </div> </div> document.querySelector(".container") .addEventListener("click", function() { console.log("Container clicked"); }); document.querySelector(".child") .addEventListener("click", function() { console.log("Child clicked"); }); document.querySelector(".button") .addEventListener("click", function() { console.log("Button clicked"); });

Clicking the button normally prints Button clicked, Child clicked, and Container clicked.

Stopping Event Bubbling

The event.stopPropagation() method prevents the event from moving to parent elements.

let card = document.querySelector(".card"); let deleteButton = document.querySelector(".delete-btn"); card.addEventListener("click", function() { console.log("Open card details"); }); deleteButton.addEventListener("click", function(event) { event.stopPropagation(); console.log("Delete card"); });

Clicking the delete button will not execute the card click event.

Event Delegation

Event delegation means adding one event listener to a parent element and handling events from its child elements.

let list = document.querySelector("#taskList"); list.addEventListener("click", function(event) { if (event.target.matches(".delete-btn")) { event.target.closest("li").remove(); } });

Advantages

  • Fewer event listeners are required.
  • Works with dynamically added elements.
  • Improves code organization.
  • Uses event bubbling efficiently.

setTimeout()

The setTimeout() method runs a function once after a specified delay.

console.log("Start"); setTimeout(function() { console.log("Runs after 2 seconds"); }, 2000); console.log("End");

The delay is written in milliseconds. 1000 milliseconds equals 1 second.

clearTimeout()

The clearTimeout() method cancels a timeout before it executes.

let timeoutId = setTimeout(function() { console.log("This will not run"); }, 3000); clearTimeout(timeoutId);

The timer ID returned by setTimeout() must be stored in a variable.

setInterval()

The setInterval() method repeatedly runs a function after every specified interval.

let count = 0; let intervalId = setInterval(function() { count++; console.log("Count:", count); if (count === 5) { clearInterval(intervalId); } }, 1000);

This code runs once every second and stops after the count reaches 5.

clearInterval()

The clearInterval() method stops an interval from running again.

let intervalId = setInterval(function() { console.log("Running..."); }, 1000); clearInterval(intervalId);

setTimeout() vs setInterval()

setTimeout() setInterval()
Runs once Runs repeatedly
Uses clearTimeout() Uses clearInterval()
Useful for delayed actions Useful for repeated actions
Example: hide notification Example: update clock

Complete Timer Example

let message = document.querySelector("#message"); let startButton = document.querySelector("#start"); let stopButton = document.querySelector("#stop"); let timerId; startButton.addEventListener("click", function() { let seconds = 0; clearInterval(timerId); timerId = setInterval(function() { seconds++; message.innerText = "Running for " + seconds + " seconds"; }, 1000); }); stopButton.addEventListener("click", function() { clearInterval(timerId); message.innerText = "Timer stopped"; });

Asynchronous Timer Behavior

JavaScript timers do not block the remaining code. They schedule callbacks for later execution.

console.log("First"); setTimeout(function() { console.log("Third"); }, 0); console.log("Second");

The output will be First, Second, and then Third, even though the timeout delay is zero.

Best Practices

  • Use addEventListener() instead of inline event attributes.
  • Keep event handler functions small and clear.
  • Use meaningful function names.
  • Use event delegation for repeated child elements.
  • Store timer IDs in variables.
  • Clear unused timeouts and intervals.
  • Use stopPropagation() only when required.
  • Remember that timer delays are in milliseconds.

Common Mistakes

  • Writing functionName() instead of functionName in addEventListener().
  • Forgetting to accept the event object.
  • Confusing event.target with event.currentTarget.
  • Ignoring event bubbling.
  • Using stopPropagation() unnecessarily.
  • Starting multiple intervals accidentally.
  • Forgetting to clear intervals.
  • Treating timer values as seconds instead of milliseconds.
  • Expecting setTimeout() to block JavaScript execution.

Important Points

  • Events allow JavaScript to respond to user actions.
  • addEventListener() attaches an event handler.
  • The event object contains information about the event.
  • event.target shows where the event started.
  • event.currentTarget shows which listener is running.
  • Event bubbling moves events from child to parent.
  • stopPropagation() stops further propagation.
  • Event delegation uses one parent listener for many children.
  • setTimeout() runs once after a delay.
  • setInterval() runs repeatedly.
  • clearTimeout() and clearInterval() cancel timers.
  • Timer values are measured in milliseconds.

    It is a technique where a parent element handles events from its child elements.

Final Takeaways

JavaScript events connect user actions with application logic, while event bubbling explains how those actions move through nested DOM elements. addEventListener() is the standard way to build interactive behavior, event delegation makes dynamic interfaces more efficient, and stopPropagation() provides control when nested actions must remain separate. setTimeout() and setInterval() make delayed and repeated tasks possible, but their timer IDs should be stored and cleared whenever the action is no longer required. Mastering these concepts is essential before learning callbacks, promises, async/await, APIs, and larger frontend applications.
