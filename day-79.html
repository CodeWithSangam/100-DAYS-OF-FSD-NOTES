Day 79 - JavaScript try, catch, throw and Error Handling

🎥 Watch Tutorial #79

In this tutorial, we learn how JavaScript handles runtime errors using try, catch, throw, and finally. Error handling prevents an application from stopping unexpectedly and allows developers to show meaningful messages when something goes wrong. These concepts are especially useful while validating user input, processing JSON, calling APIs, accessing unavailable data, and executing code that may fail.

What is an Error in JavaScript?

An error is a problem that occurs while JavaScript code is being parsed or executed. An error can stop the normal flow of the program.

Start Program ↓ Execute JavaScript Code ↓ An Error Occurs ↓ Normal Execution Stops ↓ Error Message is Displayed

Why is Error Handling Important?

  • Prevents the complete application from crashing.
  • Displays meaningful messages to users.
  • Makes debugging easier.
  • Handles invalid user input.
  • Handles failed API requests.
  • Protects important application operations.
  • Allows the remaining code to continue running.
  • Improves application reliability.

Common Types of JavaScript Errors

Error Type Meaning
SyntaxError JavaScript syntax is incorrect
ReferenceError A variable or function does not exist
TypeError An operation is performed on an incorrect data type
RangeError A value is outside the allowed range
URIError An invalid URI function is used
Custom Error An error created manually by the developer

Syntax Error

A SyntaxError occurs when JavaScript code does not follow the correct language syntax.

console.log("Hello JavaScript";

The closing parenthesis is missing, so JavaScript cannot correctly parse the code.

Reference Error

A ReferenceError occurs when JavaScript tries to access a variable or function that has not been declared.

console.log(username);

If username has not been declared, JavaScript produces a ReferenceError.

Type Error

A TypeError occurs when an operation is performed on a value of an incompatible type.

let number = 25; number.toUpperCase();

The toUpperCase() method works with strings, not numbers.

Range Error

A RangeError occurs when a value is outside the range of acceptable values.

let number = 10; number.toFixed(200);

The number of digits supplied to toFixed() exceeds the allowed range.

What is try...catch?

The try...catch statement is used to execute code that may produce an error and handle that error without stopping the complete program.

try { // Code that may produce an error } catch (error) { // Code that handles the error }

Basic try...catch Example

try { console.log(username); } catch (error) { console.log("An error occurred"); } console.log("Program continues");

The incorrect statement produces an error, but the catch block handles it. Therefore, the final console statement still executes.

How try...catch Works

Execute try Block ↓ If No Error Occurs ↓ Skip catch Block ↓ Continue Program If an Error Occurs ↓ Stop Remaining try Code ↓ Execute catch Block ↓ Continue Program

The try Block

The try block contains code that may generate an error.

try { let result = riskyOperation(); console.log(result); }

JavaScript monitors the statements inside the try block while they execute.

The catch Block

The catch block executes only when an error occurs inside the corresponding try block.

try { undefinedFunction(); } catch (error) { console.log("The function does not exist"); }

The Error Object

When an error occurs, JavaScript passes an Error object to the catch block.

try { console.log(undefinedVariable); } catch (error) { console.log(error); console.log(error.name); console.log(error.message); console.log(error.stack); }
Property Meaning
error.name Name or type of the error
error.message Description of the error
error.stack Information about where the error occurred

Using error.name

try { let value = unknownValue; } catch (error) { console.log(error.name); }

The output will normally be ReferenceError.

Using error.message

try { let user = null; console.log(user.name); } catch (error) { console.log(error.message); }

The message property provides a readable description of what went wrong.

Code After an Error Inside try

When an error occurs inside the try block, the remaining statements inside that try block are skipped.

try { console.log("First statement"); console.log(undefinedVariable); console.log("This will not execute"); } catch (error) { console.log("Error handled"); } console.log("Program continues");

try...catch Does Not Handle Syntax Errors Everywhere

The try...catch statement handles runtime errors in executable code. A syntax error that prevents the script from being parsed may occur before the try block can execute.

try { console.log("Hello"; } catch (error) { console.log(error.message); }

The JavaScript parser may reject the entire script because the syntax itself is invalid.

Handling JSON Parsing Errors

JSON.parse() produces an error when it receives invalid JSON text.

let jsonData = `{ "name": "Sangam", "age": 20 }`; try { let user = JSON.parse(jsonData); console.log(user); } catch (error) { console.log("Invalid JSON data"); }

Invalid JSON Example

let jsonData = `{ name: "Sangam" }`; try { let user = JSON.parse(jsonData); console.log(user); } catch (error) { console.log("JSON parsing failed"); console.log(error.message); }

Valid JSON requires property names to be enclosed in double quotes.

What is the throw Statement?

The throw statement is used to create and raise a custom error manually.

throw new Error("Something went wrong");

When throw executes, the normal flow stops and JavaScript searches for a matching catch block.

Basic throw Example

let age = 15; try { if (age < 18) { throw new Error( "User must be at least 18 years old" ); } console.log("User is eligible"); } catch (error) { console.log(error.message); }

Throwing a String

JavaScript allows any value to be thrown, but throwing an Error object is usually better.

try { throw "Invalid input"; } catch (error) { console.log(error); }

Throwing an Error Object

try { throw new Error("Invalid input"); } catch (error) { console.log(error.name); console.log(error.message); console.log(error.stack); }

An Error object contains useful properties such as name, message, and stack.

Custom Input Validation

function validateAge(age) { if (age === "") { throw new Error("Age is required"); } if (isNaN(age)) { throw new Error("Age must be a number"); } if (age < 18) { throw new Error( "Age must be 18 or above" ); } return "Age is valid" ; } try { let result=validateAge(16); console.log(result); } catch (error) { console.log(error.message); }

Validating a Division Operation

function divide(a, b) { if (typeof a !== "number" || typeof b !== "number") { throw new TypeError( "Both values must be numbers" ); } if (b === 0) { throw new Error( "Division by zero is not allowed" ); } return a / b; } try { let result = divide(20, 0); console.log(result); } catch (error) { console.log(error.message); }

What is finally?

The finally block executes after try and catch, whether an error occurs or not.

try { console.log("Try block"); } catch (error) { console.log("Catch block"); } finally { console.log("Finally block"); }

finally with an Error

try { console.log(undefinedVariable); } catch (error) { console.log("Error handled"); } finally { console.log("This always executes"); }

finally without an Error

try { console.log("No error occurred"); } catch (error) { console.log(error.message); } finally { console.log("Operation completed"); }

The finally block executes even when the catch block is skipped.

Why is finally Useful?

  • Hide loading indicators.
  • Close database connections.
  • Stop timers.
  • Reset form states.
  • Release application resources.
  • Remove temporary data.
  • Perform cleanup operations.
  • Display a final completion message.

try...catch...finally Flow

try { // Risky operation } catch (error) { // Handle failure } finally { // Always perform cleanup }

Return Statement and finally

A finally block normally executes even when the try or catch block contains a return statement.

function getMessage() { try { return "Message from try"; } finally { console.log("Finally executed"); } } console.log(getMessage());

The finally statement executes before the function returns its final value.

Nested try...catch

A try...catch statement can be placed inside another try block.

try { console.log("Outer try"); try { JSON.parse("Invalid JSON"); } catch (innerError) { console.log( "Inner error:", innerError.message ); } } catch (outerError) { console.log( "Outer error:", outerError.message ); }

Rethrowing an Error

A catch block can handle a specific error and throw it again so another catch block can process it.

function processData(data) { try { if (!data) { throw new Error( "Data is required" ); } return data.toUpperCase(); } catch (error) { console.log( "Error inside processData" ); throw error; } } try { processData(""); } catch (error) { console.log( "Final error:", error.message ); }

Different Error Constructors

new Error("General error"); new TypeError("Incorrect data type"); new ReferenceError("Variable not found"); new RangeError("Value outside range"); new SyntaxError("Invalid syntax");

Using a suitable error type makes debugging and error handling more meaningful.

Handling Different Error Types

try { let number = 25; number.toUpperCase(); } catch (error) { if (error instanceof TypeError) { console.log( "A type error occurred" ); } else if ( error instanceof ReferenceError ) { console.log( "A reference error occurred" ); } else { console.log( "An unknown error occurred" ); } }

What is instanceof?

The instanceof operator checks whether an object was created from a particular constructor.

try { throw new TypeError( "Value must be a string" ); } catch (error) { console.log( error instanceof TypeError ); console.log( error instanceof Error ); }

Creating a Custom Error Class

A custom error class can extend the built-in Error class.

class ValidationError extends Error { constructor(message) { super(message); this.name = "ValidationError"; } } try { throw new ValidationError( "Email address is invalid" ); } catch (error) { console.log(error.name); console.log(error.message); }

Form Validation Example

let form = document.querySelector("#userForm"); form.addEventListener( "submit", function(event) { event.preventDefault(); let username = document.querySelector("#username").value; let message = document.querySelector("#message"); try { if (username.trim() === "") { throw new Error( "Username cannot be empty" ); } if (username.length < 3) { throw new Error( "Username must contain at least 3 characters" ); } message.innerText="Form submitted successfully" ; } catch (error) { message.innerText=error.message; } } );

Error Handling with Async/Await

try...catch is commonly used to handle rejected promises inside async functions.

async function getData() { try { let response = await fetch( "https://example.com/api/data" ); if (!response.ok) { throw new Error( "Request failed: " + response.status ); } let data = await response.json(); console.log(data); } catch (error) { console.log( "Fetch error:", error.message ); } } getData();

API Request with finally

let loader = document.querySelector("#loader"); async function loadUsers() { try { loader.style.display = "block"; let response = await fetch( "https://jsonplaceholder.typicode.com/users" ); if (!response.ok) { throw new Error( "Unable to load users" ); } let users = await response.json(); console.log(users); } catch (error) { console.log(error.message); } finally { loader.style.display = "none"; } } loadUsers();

The loader is hidden whether the API request succeeds or fails.

Promise catch() vs try...catch

Promise catch() try...catch
Used with promise chains Commonly used with async/await
Handles rejected promises Handles synchronous and awaited errors
Uses .catch() Uses catch block
Works after then() Wraps risky code directly

Promise Error Handling

fetch( "https://example.com/api/data" ) .then(function(response) { if (!response.ok) { throw new Error( "HTTP error: " + response.status ); } return response.json(); }) .then(function(data) { console.log(data); }) .catch(function(error) { console.log(error.message); });

Errors Inside setTimeout()

A surrounding try...catch cannot catch an error that occurs later inside an asynchronous callback.

try { setTimeout(function() { throw new Error( "Timer error" ); }, 1000); } catch (error) { console.log( "This catch may not run" ); }

The error should be handled inside the asynchronous callback itself.

Correct Timer Error Handling

setTimeout(function() { try { throw new Error( "Timer error" ); } catch (error) { console.log(error.message); } }, 1000);

Safe Property Access

Optional chaining can prevent some property-access errors when values may be null or undefined.

let user = null; console.log(user?.profile?.name);

Instead of throwing an error, optional chaining returns undefined when an intermediate value does not exist.

Default Values with Nullish Coalescing

let user = null; let username = user?.profile?.name ?? "Guest"; console.log(username);

The nullish coalescing operator provides a default value when the result is null or undefined.

Complete Validation Example

function registerUser(user) { try { if (!user) { throw new Error( "User data is required" ); } if (!user.name || user.name.trim() === "") { throw new Error( "Name is required" ); } if (!user.email || !user.email.includes("@")) { throw new Error( "Valid email is required" ); } if (user.age < 18) { throw new Error( "User must be at least 18" ); } return { success: true, message: "Registration successful" }; } catch (error) { return { success: false, message: error.message }; } finally { console.log( "Registration attempt completed" ); } } let result=registerUser({ name: "Sangam" , email: "sangam@example.com" , age: 20 }); console.log(result);

Best Practices

  • Handle only code that may fail inside try.
  • Do not place the complete application inside one try block.
  • Use meaningful error messages.
  • Throw Error objects instead of plain strings.
  • Use suitable error constructors.
  • Display user-friendly messages in the interface.
  • Log detailed errors for debugging.
  • Use finally for cleanup operations.
  • Validate input before processing it.
  • Do not silently ignore errors.
  • Handle API response status manually.
  • Create custom error classes when useful.

Common Mistakes

  • Leaving the catch block empty.
  • Using one try block for too much code.
  • Showing technical stack traces directly to users.
  • Throwing unclear error messages.
  • Throwing plain strings instead of Error objects.
  • Forgetting that code after an error in try is skipped.
  • Expecting try...catch to fix an error automatically.
  • Forgetting to check response.ok in Fetch API requests.
  • Assuming an outer try catches future timer errors.
  • Using finally to return or override important values.
  • Catching errors without logging or handling them.
  • Using errors for normal application flow unnecessarily.

Interview Questions

  1. What is error handling in JavaScript?
    Error handling is the process of detecting, managing, and responding to errors without unexpectedly stopping the complete application.
  2. What is the purpose of the try block?
    The try block contains code that may produce an error.
  3. When does the catch block execute?
    The catch block executes when an error occurs inside its corresponding try block.
  4. What is the Error object?
    It is an object containing information about an error, including its name, message, and stack.
  5. What does error.name contain?
    It contains the type or name of the error.
  6. What does error.message contain?
    It contains a readable description of the error.
  7. What does the throw statement do?
    The throw statement manually creates and raises an error.
  8. Can JavaScript throw values other than Error objects?
    Yes, but using an Error object is recommended because it provides useful error information.
  9. What is the purpose of finally?
    The finally block executes after try and catch whether an error occurs or not.
  10. What happens to the remaining try code after an error?
    The remaining statements inside the try block are skipped.
  11. What is a ReferenceError?
    It occurs when JavaScript tries to access an undeclared variable or function.
  12. What is a TypeError?
    It occurs when an operation is performed on an incompatible data type.
  13. How can errors be handled with async/await?
    Place the awaited operations inside a try block and handle failures in catch.
  14. Does fetch() reject for every HTTP error?
    No. Status codes such as 404 may still return a fulfilled Response, so response.ok should be checked.
  15. What is a custom error class?
    It is a developer-created class that usually extends the built-in Error class.
  16. What does instanceof do in error handling?
    It checks whether an error was created from a particular error constructor.
  17. Can try...catch catch an error inside a later setTimeout callback?
    Not when the try block finishes before the callback runs. The asynchronous callback needs its own error handling.
  18. Why should errors not be ignored?
    Ignoring errors makes debugging difficult and may leave the application in an incorrect state.

Final Takeaways

JavaScript error handling helps applications respond safely when something goes wrong. The try block contains code that may fail, while catch receives and handles the resulting Error object. The throw statement allows developers to create meaningful custom errors for invalid data and unsuccessful operations. The finally block performs cleanup regardless of whether the operation succeeds or fails. These concepts are essential for form validation, JSON processing, API requests, authentication, file handling, payments, and reliable web application development.
